# Security

This file covers what `boxctl` (the CLI in this repository) does with your
credentials, where they end up, and how to report a vulnerability. It
describes the CLI. The control plane it talks to (`boxctl-vms`) is a
separate repository; anything below about the server is limited to what
this CLI can show from its side.

## Reporting a vulnerability

Email **security@boxctl.io**. Please don't open a public issue for a
vulnerability.

Include the `boxctl version`, what you did, and what you saw. If the
problem involves a token, rotate it first, then tell us.

## Isolation

- Every box is its own Firecracker microVM, with its own guest kernel.
  Boxes don't share a kernel with each other.
- Destroying a box (`boxctl rm`) stops its Firecracker process and removes
  its VM directory, which holds the rootfs, from the host (`onctl`'s
  Firecracker provider, `Destroy`). That is a file deletion, not a secure
  erase. Backups you made earlier (`boxctl download`, the dashboard's
  Backup button) are separate copies and stay until they age out or you
  delete them.
- Every `/api/vms*` request the CLI makes is scoped by the server to the
  owner of your personal token. The CLI never computes or sees that scope.
- Inside a box you are `root`. Anything you or an agent runs there can
  read everything else on that box, including the credentials described
  below while they are present.

## What the CLI keeps on your machine

| What | Where | Notes |
| --- | --- | --- |
| boxctl personal token | `~/.boxctl/config.json`, mode `0600` | Sent only to the configured API URL. |
| SSH key for boxes | `~/.boxctl/claude/id_ed25519` | Generated by `boxctl claude`, no passphrase. Its public half is added to `root`'s `authorized_keys` on each box. |
| Claude token | macOS Keychain; elsewhere `~/.boxctl/claude/oauth-token`, mode `0600` | Saved by `boxctl claude login`. Removed by `boxctl claude logout`. `CLAUDE_CODE_OAUTH_TOKEN` in your environment is used instead if set. |

`boxctl claude` does not store a GitHub token locally. It reads
`BOXCTL_GITHUB_TOKEN`, or else asks `gh auth token`, once per box it sets
up.

## Claude Code credentials

With `--claude-auth auto` or `token` (the default is `auto`), Claude on the
box gets the token as `CLAUDE_CODE_OAUTH_TOKEN`:

1. `boxctl` writes it to a file under `/run/boxctl/` on the box. `/run` is
   a tmpfs, so the file is in memory, not on the box's disk. The file is
   created with `umask 077`, so it is readable by root only.
2. The token reaches that file on the standard input of an ssh command,
   not on a command line, so it doesn't show up in `ps`.
3. The command tmux runs to start Claude sources the file and deletes it
   right away, before Claude starts.

The token is not part of any box image and `boxctl` doesn't print or log
it. Claude's process keeps it in its environment while it runs, so Claude
and every command it runs can read it. If a box is paused, the snapshot
includes memory, so the token can be in a snapshot or backup of a box
whose Claude was running at that point. `--claude-auth api-key` works the
same way with `ANTHROPIC_API_KEY`.

This token is a `claude setup-token` token. It can make model requests and
is not your normal Claude login. If you think it leaked, make a new one with
`claude setup-token` and run `boxctl claude login` again.

## GitHub credentials

`--github` has two modes.

**`store` (the default).** A token is logged in to `gh` on the box when
the box is set up, and `gh` becomes git's credential helper there. The
token is `BOXCTL_GITHUB_TOKEN` if set, and otherwise the output of `gh
auth token` on your machine. With neither, an attended run goes on with a
warning and no GitHub access; `--goal`, which must push and open a pull
request without you, refuses before making a box. The token reaches the
box on the standard input of an ssh command, never a command line.

The token stays on the box until the box is destroyed, and is in any
backup or pause snapshot taken meanwhile. An ephemeral box (the default
`boxctl claude` run) is deleted when the run ends; a `--keep`, `--task`
or `--goal` box is not. Your `gh auth token` can usually do whatever you
can, to every repository you reach, so for those set
`BOXCTL_GITHUB_TOKEN` to a fine-grained token for the one repository,
with only Contents and Pull requests read/write, and an expiry.

**`off`.** The box gets no GitHub credentials. Your git `user.name` and
`user.email` are still copied to the box in every mode.

## Unattended runs

`boxctl claude --goal` runs Claude with `--dangerously-skip-permissions`
(and `IS_SANDBOX=1`, so it will run as root) and nobody to approve
anything. Treat the box as untrusted and the stored GitHub token as
reachable by whatever Claude reads or runs there, including content from
the repository or the web. This is why the token should be scoped to one
repository.

## What reaches the boxctl.io servers

- Your boxctl personal token, with every API request.
- Everything you type or run through `boxctl ssh`, `exec`, `port-forward`
  and `ssh-proxy` passes through boxctl.io's tunnel.
- `boxctl claude` talks to the box over real ssh, run through `ssh-proxy`.
  ssh encrypts it between your machine and the box, so the relay carries
  ciphertext. However, `boxctl claude` runs ssh with
  `StrictHostKeyChecking=no` and no known-hosts file, because every box
  has fresh host keys and the tunnel is already authenticated with your
  token. That means the box's identity is vouched for by boxctl.io, not
  checked by ssh: you trust boxctl.io not to impersonate your box.
- `boxctl claude` adds its public key to the box over the exec endpoint.

The Claude token and GitHub tokens are not sent to the boxctl API. They
go to the box over that ssh connection. The control plane keeps only a
SHA-256 hash of your boxctl personal token, with its label, owner prefix,
and creation and last-used times, in a JSON file written with mode `0600`
(`boxctl-vms`, `internal/auth/tokens.go`). It can't hand the token back,
and a personal token can't mint another one. Revoke yours from the
dashboard's tokens page.

## What you should do

- Set `BOXCTL_GITHUB_TOKEN` to a fine-grained GitHub token limited to one
  repository, with the fewest permissions, and an expiry, rather than
  letting the box have your `gh` login's token.
- Destroy a box when you're done (`boxctl rm <name>`). A box the idle
  reaper pauses still exists, with its disk and its GitHub token.
- Don't put secrets in a project's tracked or non-ignored files: the
  project is copied to the box (git-tracked and untracked-not-ignored
  files, plus `.git`).
- Revoke tokens you think leaked: your boxctl token on the dashboard's
  tokens page, the Claude token by making a new one, GitHub tokens in GitHub's
  settings.
